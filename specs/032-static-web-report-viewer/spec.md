# Feature Specification: Static Web Report Viewer

**Feature Branch**: `032-static-web-report-viewer`

**Created**: 2026-05-15

**Status**: Draft

**Input**: Project roadmap Phase 2: build the first web UI around existing canonical report artifacts only. The viewer should consume canonical report JSON and render a polished, browser-openable dashboard without live run control.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Open a Canonical Report in a Browser (Priority: P1)

As a vLLM Optimizer user, I want to turn a canonical report JSON into an HTML dashboard so that I can inspect the recommendation, candidate ranking, metrics, and provenance visually.

**Why this priority**: This is the first tangible web interface while preserving canonical CLI artifacts as the source of truth.

**Independent Test**: Generate an HTML viewer from a canonical report fixture and verify that the file contains the recommendation status, candidate table, chart dataset values, and provenance links.

**Acceptance Scenarios**:

1. **Given** a canonical report where baseline wins, **When** the viewer is generated, **Then** the page clearly shows the keep-baseline decision and supporting metrics.
2. **Given** a canonical report with multiple candidates, **When** the viewer is generated, **Then** the page shows a ranked comparison and metric visualization for all candidates.

---

### User Story 2 - Preserve Web-Ready Separation (Priority: P2)

As a future dashboard developer, I want the HTML viewer to read only canonical report data so that report logic remains in the deterministic artifact layer.

**Why this priority**: The web layer must not diverge from the CLI recommendation engine.

**Independent Test**: Verify the viewer generator accepts canonical report JSON and does not require raw ranking, summary, or results artifacts.

**Acceptance Scenarios**:

1. **Given** only a canonical report JSON, **When** the viewer is generated, **Then** the viewer contains all visible report data without loading additional optimizer artifacts.

### Edge Cases

- Canonical report is missing required top-level sections.
- Candidate metrics contain null values.
- There are no recommendable candidates.
- Long candidate identifiers must remain readable without layout overflow.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST generate a standalone HTML file from a canonical report JSON artifact.
- **FR-002**: The HTML viewer MUST show recommendation status, objective, summary, rationale, next actions, candidates, metric comparisons, and provenance.
- **FR-003**: The viewer MUST use the canonical report as its only optimizer data input.
- **FR-004**: The viewer MUST be usable by opening the generated HTML file directly in a browser.
- **FR-005**: The viewer MUST avoid hidden network dependencies.
- **FR-006**: The viewer MUST handle null metric values with readable fallback text.
- **FR-007**: The viewer MUST be deterministic when regenerated from unchanged canonical report input.

### Experiment Requirements *(include for optimizer features)*

- **ER-001**: Feature MUST report the objective family already present in the canonical report.
- **ER-002**: Feature MUST preserve provenance from the canonical report.
- **ER-003**: Feature MUST perform no GX10 actions.
- **ER-004**: Feature MUST not mutate source run artifacts.
- **ER-005**: Feature MUST support local preview without live remote use.

### Key Entities *(include if feature involves data)*

- **Web Report Viewer**: Standalone HTML dashboard generated from a canonical report.
- **Viewer Section**: Recommendation, metrics, candidates, chart, provenance, and next-action regions.
- **Canonical Report Input**: Machine-readable report JSON generated by Spec 031.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: A user can open a generated HTML report directly in a browser and identify the recommendation in under 30 seconds.
- **SC-002**: The viewer displays at least five report views: recommendation, objective summary, candidate comparison, metric visualization, and provenance.
- **SC-003**: Regenerating the viewer from unchanged input produces identical HTML content.
- **SC-004**: Tests verify baseline-winning and non-baseline-winning reports render without requiring raw ranking artifacts.

## Assumptions

- This phase creates a static viewer, not a long-running web server.
- A richer interactive web app will build on this viewer and canonical report contract later.
- Generated HTML reports live under ignored artifact directories unless the user explicitly saves examples elsewhere.
