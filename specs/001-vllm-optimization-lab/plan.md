# Implementation Plan: vLLM Optimization Lab

**Branch**: `001-vllm-optimization-lab` | **Date**: 2026-05-13 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-vllm-optimization-lab/spec.md`

## Summary

Build a Python CLI/library that turns operator-authored experiment definitions
into deterministic trial plans, previews all remote GX10 actions in dry-run
mode, accepts fixture artifacts, and ranks configurations for named objective
families. The first increment avoids live SSH mutation and proves the core
workflow locally with tests and fixtures.

## Technical Context

**Language/Version**: Python 3.11+; local workstation currently has Python and
uv available

**Primary Dependencies**: Standard library for MVP runtime; pytest for tests;
PyYAML optional for YAML experiment files with JSON supported as the baseline

**Storage**: Filesystem artifacts under `artifacts/`; JSON/JSONL for trial
plans, command previews, fixture metrics, and reports

**Testing**: pytest unit and integration tests

**Target Platform**: Local Windows controller now; remote Linux GX10 later via
configured SSH

**Project Type**: Python CLI plus importable library

**Performance Goals**: Generate at least 100 trial definitions in under 1
second locally; rank fixture artifacts for at least 100 trials in under 1
second locally

**Constraints**: No live SSH required for MVP; all remote actions dry-run by
default; no secrets committed; deterministic output for identical definitions

**Scale/Scope**: Initial scope covers deterministic planning, dry-run preview,
fixture ingestion, and throughput/latency ranking; live vLLM benchmarking is a
future feature gated by the same safety model

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Deterministic Experiments**: PASS. Experiment definitions include seeds,
  objective, parameter space, workload, model identity, vLLM version, target
  host profile, and environment metadata fields. Trial ordering is generated by
  deterministic Cartesian expansion sorted by parameter name.
- **Complete Traceability**: PASS. Plan writes trial plans, command previews,
  fixture/raw metrics, validation errors, and ranked reports as separate JSON
  artifacts with cross-references by trial id.
- **Remote Safety and Reversibility**: PASS. MVP provides dry-run preview only.
  Remote action rendering is allowlist-based and classifies read-only,
  session-mutating, and persistent-mutating actions.
- **Objective-Driven Optimization**: PASS. Ranking requires objective family,
  constraints, metrics, and tie-breakers. Throughput and latency are implemented
  first; other families are accepted in plans but require future scorers.
- **Testable, Modular Automation**: PASS. Modules are separated into
  experiment loading, planning, action rendering, safety validation, artifact
  IO, scoring, and CLI surfaces with focused tests.

## Experiment and Safety Design

**Objective Family**: Initial implementation supports deterministic planning
for all declared families and scoring for throughput and latency.

**Benchmark Inputs**: Experiment definitions include prompt corpus id, request
mix name, concurrency levels, seeds, model id, vLLM version, and bounded vLLM
parameter values. Fixture metrics simulate benchmark outputs for local ranking.

**Remote Actions**: Dry-run renders read-only probe commands, vLLM start/stop
intent, benchmark intent, artifact copy intent, and cleanup intent. Live SSH is
not executed in this feature.

**Artifacts**: JSON trial plan, JSON command preview, JSONL raw result fixtures
or copied metrics, JSON validation errors, and JSON ranked recommendation
report under `artifacts/<experiment-id>/`.

**Rollback/Cleanup**: MVP cleanup is represented in the dry-run preview. Future
live execution must implement process termination and restoration steps before
session-mutating actions can run.
